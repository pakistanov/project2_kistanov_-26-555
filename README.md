# Primitive DB

Учебная консольная база данных на Python 3.12 и новее.
Программа создаёт таблицы с типами `int`, `str`, `bool` и выполняет
CRUD-операции: добавление, чтение, изменение и удаление записей.
Структура таблиц и данные сохраняются в JSON-файлах.

## Запуск

Для работы с исходным кодом выполните из корня проекта:

```powershell
uv sync
uv run database
```

Команда `uv run database` запускает текущий код проекта.
Для установки собранного пакета см. раздел «Сборка и проверка» ниже.
Команда `project` также поддерживается как второе имя запуска.

## Команды

### Управление таблицами

| Команда | Действие |
| --- | --- |
| `create_table <имя> <столбец:тип> ...` | Создать таблицу |
| `list_tables` | Показать имена таблиц |
| `drop_table <имя>` | Удалить таблицу вместе с записями |
| `info <имя>` | Показать столбцы и количество записей |

### CRUD-операции

| Команда | Действие |
| --- | --- |
| `insert into <имя> values (<значение1>, ...)` | Добавить запись |
| `select from <имя>` | Показать все записи |
| `select from <имя> where <столбец> = <значение>` | Найти записи по условию |
| `update <имя> set <столбец> = <значение> where <столбец> = <значение>` | Обновить подходящие записи |
| `delete from <имя> where <столбец> = <значение>` | Удалить подходящие записи |

`help` показывает справку, `exit` завершает работу.
Результаты `select` выводятся через PrettyTable.

### Правила ввода

- Имена таблиц и столбцов — допустимые идентификаторы Python, например
  `users`, `is_active`, `товары`. Имена чувствительны к регистру.
- Столбец `ID:int` добавляется автоматически и всегда стоит первым.
  Явно указанный `ID:int` не дублируется. Повторяющиеся столбцы запрещены.
- В `insert` перечисляются все значения в порядке столбцов, без ID.
  Все поля обязательны.
- Строки заключаются в кавычки: `"Sergei"` или `'Sergei'`.
  Целые числа вводятся без кавычек, логические значения — `true` и `false`.
- Поддерживается одно условие равенства в `where`.
  В `set` можно указать несколько присваиваний через запятую.
- Новый ID равен максимальному существующему ID плюс один;
  для пустой таблицы — 1. После удаления последнего по номеру ID он может
  использоваться снова. При изменении ID он должен быть положительным и уникальным.

## Пример работы

После запуска `database` команды вводятся внутри программы:

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: insert into users values ("Sergei", 28, true)
Функция insert выполнилась за 0.000 секунд
Запись с ID=1 успешно добавлена в таблицу "users".

>>>Введите команду: select from users where age = 28
Функция select выполнилась за 0.000 секунд
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+

>>>Введите команду: update users set age = 29 where ID = 1
Запись с ID=1 в таблице "users" успешно обновлена.

>>>Введите команду: delete from users where ID = 1
Вы уверены, что хотите выполнить "удаление записей"? [y/n]: y
Запись с ID=1 успешно удалена из таблицы "users".

>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0

>>>Введите команду: exit
```

Время выполнения в примере условное: при запуске программа измеряет его сама.
Таблица `users` — пример; можно создавать таблицы с другими столбцами.

## Хранение данных

Файлы создаются относительно текущей папки терминала:

```text
db_meta.json       # имена таблиц и структура столбцов
data/
└── users.json     # записи таблицы users
```

Изменения сохраняются сразу. При повторном запуске из той же папки
данные остаются доступными. `drop_table` удаляет и структуру таблицы,
и соответствующий файл с записями.

При отсутствии файла метаданных программа начинает с пустой базы.
При повреждённых метаданных выводит ошибку и завершает работу.
Ошибка чтения данных таблицы отменяет текущую команду.
Для записи JSON сначала создаётся временный файл, затем заменяется основной.

## Декораторы и замыкания

Реализация находится в `src/primitive_db/decorators.py`.

| Механизм | Поведение |
| --- | --- |
| `handle_db_errors` | Обрабатывает `FileNotFoundError`, `KeyError`, `ValueError` и другие исключения |
| `confirm_action(action_name)` | Запрашивает подтверждение перед `drop_table` и `delete` |
| `log_time` | Показывает время выполнения `insert` и `select` по `time.monotonic()` |
| `create_cacher()` | Возвращает `cache_result(key, value_func)` со словарём кэша в замыкании |

Для удаления требуется ответ `y`; любой другой ответ отменяет действие.
При ошибке или отмене результат операции не сохраняется и сообщение об успехе
не выводится.

Повторные выборки используют кэш в памяти. Ключ учитывает содержимое записей
и условие, поэтому после изменения данных возвращается актуальный результат.
Данные продолжают читаться из JSON: кэш сохраняет результат фильтрации.
При перезапуске программы кэш пуст.

## Сборка и проверка

Проверка кода, сборка и проверка метаданных выполняются из корня проекта:

```powershell
uv run ruff check .
uv build
uvx twine check dist/*
```

Установка собранной версии как отдельной команды:

```powershell
uv tool install --force --link-mode copy .\dist\primitive_db-0.4.0-py3-none-any.whl
database
```

`database` запускает установленную сборку. Чтобы обновить её после изменений
кода, повторите сборку и установку.
Если папка инструментов отсутствует в PATH, выполните `uv tool update-shell`
и откройте новый терминал.
